# Security: the Aspire Atlas mod

Report a vulnerability as for the rest of this repository: see the root [SECURITY.md](../../SECURITY.md).

## What ships

One Claude Code mod: a TypeScript function-hooks module (`hooks/register.tsx` and the files it imports), its state contract (`types/index.d.ts`), and its tests. No shell scripts or binaries, nothing installed, no environment variables or API keys. It depends on the `aspire` plugin, whose `/aspire` skill and `aspire:*` agents switch it on; `aspire` works fully without it.

## What the mod can and cannot do

The mod draws a progress bar and a band above the prompt (the `/aspire` skill's progress under the organization's name) a panel of the session's agents, which also shows Atlas token costs, a short notice above the prompt (about six seconds, cleared when you submit) that says an agent you pressed is queued in the prompt box, a prompt coach card above the bar (a one-line verdict the `/aspire` skill reports about the request you are writing, cleared when the run finishes or after five minutes), and a card for each Artifact the session publishes. It runs inside Claude Code as a function hook, and:
- stays inert until an Aspire event: a prompt typed as `/aspire` or `/aspire:aspire`, the aspire skill running through the Skill tool, a progress report from the skill, a result from an Aspire Atlas connector tool other than `report_checkpoint`, or an `aspire:*` agent starting. Until then every hook passes the event on unchanged and records nothing (the Artifact card below included), and a `/clear` puts it back to sleep;
- reads only what is already in the session: whether a submitted prompt starts with `/aspire`, and the first line of each request (clipped to 80 characters, kept in session state as the title of the steps, never sent anywhere); the agent's own task list (its `TaskCreate`, `TaskUpdate`, `TodoWrite`, and the desktop app's `update_plan` and `wrap_up` calls) and, for the steps' estimate, how many tool calls each step took, the name of the call in flight, and which files were read or changed this request (names only, as the agent's tool calls give them); Atlas `get_status` results (token costs, the selected organization's name, and whether a brand profile and a linked channel exist), the names of other Atlas tools that answered, subagent starts and ends, the timing and token counts of model responses, and the context fill; and, for an Artifact publish only, the call's title, description and file name and the result's link, kept in memory for the card (at most 50, cleared by `/clear`, never sent anywhere);
- registers two tools that only change what is drawn: `aspire_progress`, which the `/aspire` skill calls to move the progress bar (a call from a subagent is ignored) and, through its one optional `coach` field, the prompt coach card (text only, at most 140 and 30 characters with control characters removed, shown as drawn text, nothing read or changed because of it; the field widens the tool's input and reads nothing new, and adding it is a deliberate decision that ships in a major version), and `aspire_step`, which an `aspire:*` agent calls to draw its own steps on its row in the agents panel (a call from the main session is ignored). Neither reads or changes anything else;
- never changes a tool call, a tool result, a submitted prompt, or an agent, and never calls a tool or the model. The exceptions are how two kinds of transcript row are drawn. Once the mod is on, an Aspire Atlas connector tool's call row (the `ToolUse` row, on the desktop and in VS Code only, for the Atlas tools' names and for a connector that has answered as Atlas; never the progress tools, Atlas's `report_checkpoint` analytics tool, or the organization admin connector) is drawn as the animated Aspire mark with the tool's plain name, the one-line description the call carries in its `context` input (less the `[runId]` an agent puts at its start), and its state (running, failed, interrupted); the mark's squares shuffle only while the call runs; the call, its input, and its result are unchanged. And the result row under a published `Artifact` call (the `ToolResult` row, only when the call was a publish and its result carries an `https:` link) is drawn as a card: an icon that opens the link, the artifact's title and description, a reminder to share it with your team, and a "Post to Slack" button. Every other tool's result, an Artifact call that is not a publish, and an errored result are drawn as Claude Code draws them, and what the model reads is unchanged. Prompt writes are drafts only, each replacing what is in the prompt box (`$.prompt.fill`) and never submitted: pressing an agent in the panel puts `/aspire:aspire run {agent}` there, and pressing "Post to Slack" puts "Share this artifact on Slack: {link}. Ask me with AskUserQuestion which channel or person, write a short message, show it, and post only after I confirm." there. The person reads it and presses Enter; the mod posts nothing to Slack, and Claude, once asked, follows the confirmation rules below before any write;
- shows what it already holds in three more places, all display-only: a one-line `$.ui.status` progress under the prompt while the bar is not drawn (cleared when the run ends or the bar appears), a dim `$.ui.log` line for each new `https://claude.ai/artifact/…` link in a task notification or agent message (from a `session.receive` observer that passes every message on unchanged and never consumes or alters it; links are remembered in memory, at most 100, cleared by `/clear`), and a read of `$.agent.list()` to mark panel rows for agents the session no longer lists as finished. The Artifact card also reads the link from a plain-text result. These additions widen what the mod does, which is a deliberate decision that ships in a major version;
- brands the sites Claude Code draws itself, all display-only, only while the mod is on, and each keeping Claude Code's own drawing: the Aspire mark (a small cell mark in the terminal, which draws no Svg) beside an Atlas tool call's row (the `ToolUse` row; in the terminal the mark sits beside Claude Code's own row) and beside a collapsed run of Atlas calls (`ToolGroup`, only when it holds an Atlas call and every call in it is one, `report_checkpoint` calls left out, and the person has not expanded it); the mark and the current step of the `/aspire` flow above the question dialog (`AskUserQuestion`, only while the skill is reporting progress, with Claude Code's dialog kept exactly once, so its options, answers, and what the model reads are unchanged); the words "Aspire Atlas" and the step after the spinner's own word and animation (`Spinner`, only while the skill is reporting progress); where the running flow stands after the line that closes a turn (`TurnDuration`, terminal, only while the skill is reporting progress); " · /aspire help" after the hint under an idle prompt (`PromptHint`, terminal); and the mark beside the plugin's own `/aspire-agents-info` output (`CommandOutput`). It reads the same progress and tool names it already holds and nothing more, writes nothing, and draws nothing at the sites it does not list (the permission prompt is not a site a mod can change, and the mod leaves messages, session notices, and mode labels alone). These additions widen what the mod does, which is a deliberate decision that ships in a major version;
- makes no network calls, starts no processes, and reads or writes no files. What it shows is kept in Claude Code's session state and goes with the session. `claude plugin validate plugins/aspire-mod` lists every hook it registers and every call it makes. `/aspire-agents-info status` shows whether it is on, what switched it on, and how many Aspire events it has seen;
- ships tests (`*.test.ts`, `*.test.tsx`) that run only under `claude plugin test`.

Function hooks are an early-access Claude Code API. The mod was written and tested on Claude Code 2.1.295 and 2.1.299 and may need changes when that API changes. The `aspire` plugin's skills, agents, and connectors do not depend on it. Parts of the mod are adapted from claude-kit (MIT License); the notice is in the files that carry that code.
